Detailed Findings & Responses

F-005 FIXED
Sound toggle does not change state
Sound toggle does not change state. Audio/click sound continues after tapping the sound button.

Root Cause: The Web Audio API's AudioContext continued playing already-scheduled oscillator nodes even after the internal muted flag was set. On Android WebView, this created a perceptible delay between tapping mute and audio actually stopping.

Fix Applied: When muted, AudioContext.suspend() is now called to immediately halt all audio output. When unmuted, AudioContext.resume() reactivates it. This ensures audio stops the instant the button is tapped.

F-006 BY DESIGN
Fullscreen button not visible on Android
Fullscreen button is not visible/available on the Android main menu, so fullscreen mode could not be tested.

Explanation: The fullscreen button is intentionally hidden in the native app. The Android app runs inside a Capacitor WebView that is already fullscreen — the system navigation bar is hidden and the app occupies the entire screen. The fullscreen button only appears in the web browser version where the browser's URL bar and tabs can be hidden via the Fullscreen API. Showing it in the native app would be misleading as it has no effect.

Code Reference: if(_nativeShell()){btn.style.display='none';return;}

F-015 TEST CASE ERROR
Timer increments by 5 seconds, not 1 second
Timer increased in 5-second increments when using the + control (e.g., 3:00 → 3:05 → 3:10), whereas the test case specifies 1-second increments.

Explanation: The 5-second step size is the intended design. The timer stepper uses d = id==='t-minus' ? -5 : 5 by design. A party game timer does not need 1-second granularity — rounds are typically 30s, 45s, 60s, 90s, or longer. The stepper is supplemented by one-tap preset buttons (30s / 45s / 60s / 90s / 2min / 3min) for quick selection.

Recommendation: Update the test case specification to expect 5-second increments.

F-084 FIXED
Team tie not handled correctly
Both teams finished with equal scores (2–2), but the Game Over screen declares separate 1st and 2nd places instead of showing a tie/shared win.

Root Cause: The score screen ranking logic assigned sequential positions without checking for equal scores between teams.

Fix Applied: Teams with equal scores now share the same rank (e.g., both show 🥇 1st place). The winner announcement text now displays "🤝 It's a tie! Team A & Team B tied with X points!" instead of declaring a single winner. Confetti and winner sound still play for tied winners.

F-112 FIXED
Session resume: timer restarts from beginning
After force-closing and reopening the app, the "Game in progress" prompt appeared and the game could be resumed, but the timer restarted from the beginning instead of preserving the remaining time.

Root Cause: Game progress was only saved at round boundaries (score screen), and the save did not include the remaining timer seconds. Force-closing mid-round meant the timer value was lost.

Fix Applied: Three changes: (1) Game progress is now saved immediately when the app goes to the background (visibilitychange event), capturing mid-round state. (2) The remaining timer value (secRemaining) is now included in the save data. (3) On resume, the next round starts with the preserved remaining seconds instead of the full timer duration.

M-011 PLATFORM LIMITATION
Voice command "Yes" recognized inconsistently
Voice command "Yes" was recognized intermittently. In some attempts it worked on the first try, while in other attempts the command had to be repeated multiple times.

Explanation: The word "yes" is included in the voice recognition dictionary alongside 7 phonetic variants (yess, yeah, yea, yep, yup, yap). The recognition engine checks up to 3 alternative transcriptions per utterance (maxAlternatives: 3).

The inconsistency is an inherent limitation of the browser's SpeechRecognition API. Short, single-syllable words like "yes" have lower recognition confidence than longer words like "correct" or "skip." This varies by device microphone quality, ambient noise, accent, and the speech engine version on the device.

Recommendation to Users: Use "correct" instead of "yes" for the most reliable recognition. The setup screen tooltip already advises: Say "Correct", "Yes", "Skip", "Next" — listing the most reliable trigger first.

M-023 FIXED
Auto-rotate instructions do not match Android notification panel
With Auto-rotate disabled, the Up Top instructions only tell the user to turn the phone sideways. They do not provide instructions matching the current Android notification panel layout for enabling Auto-rotate.

Root Cause: The Android-specific orientation unlock instructions were too vague — they referenced "notification panel" without specifying that Quick Settings requires a second swipe, and did not describe what the Auto-rotate tile looks like.

Fix Applied: Updated the 3-step Android instructions to:

  1. Swipe down from the top of the screen — swipe twice to expand Quick Settings
  2. Look for the Auto-rotate tile (🔄 icon). If it says Portrait or shows a lock icon, tap it to switch to Auto-rotate
  3. Rotate your phone sideways — the screen should follow!
M-030 / M-031 / M-032 / M-033 FIXED
Timer continues running when app is backgrounded
M-030: The app did not crash during the incoming call, but the active game timer continued running in the background.
M-031: The game timer continued running in the background [when switching to WhatsApp].
M-032: After the app was moved to the background, the game timer continued running.
M-033: After the device was locked, the game continued running in the background.

Root Cause: No visibilitychange event handler existed to pause the game timer when the WebView lost focus (phone call, notification switch, home button, screen lock).

Fix Applied: A visibilitychange listener now:

  • On hidden: Immediately pauses the round timer (clearInterval) and saves game progress including remaining seconds
  • On visible: Resumes the timer from where it was paused, and re-acquires the wake lock to prevent the screen from dimming during gameplay

This covers all four scenarios: incoming calls, notification switches, home button, and screen lock/auto-lock. The timer is guaranteed to pause within the same event-loop tick as the visibility change.

N-009 FIXED
Auth tab switch distorts UI layout
Switching between Sign Up and Sign In tabs causes the UI layout to become distorted/broken. The interface does not remain visually stable when switching between authentication tabs.

Root Cause: When switching tabs, residual error states (red validation borders on input fields, error messages) from the previous tab were not fully cleared. Additionally, if the signed-in view was displayed, switching tabs could show it alongside the signed-out form. The modal's scroll position was also not reset, causing misalignment on smaller screens.

Fix Applied: The tab switch function now:

  • Clears field-invalid CSS classes from all input fields (removes red error borders)
  • Explicitly shows the signed-out form and hides the signed-in view
  • Resets the modal scroll position to the top
  • Clears all field values and error/success messages (already existed)
P-022 FIXED
Ad can be closed early via Android back button
The rewarded ad can be closed early using the Android Back/navigation button before the 30-second countdown completes, returning the user to the menu.

Root Cause: The Android hardware back button handler mapped screen-ad to screen-home in its navigation table, allowing users to exit the ad screen at any time.

Fix Applied: The back button is now blocked (no-op) while the ad screen is active. Users must either wait for the full countdown to complete (which unlocks the words) or use the on-screen "Close ad" button (which appears after 5 seconds but does NOT unlock words). This prevents bypassing the ad requirement while still giving users an exit that doesn't grant unearned rewards.

Additional Improvement: Word Transition Animation

While investigating the reported issues, we identified and fixed a performance issue with word transitions during gameplay:

  • Before: Words transitioned with a translateX(26px) slide animation that triggered layout recalculation on every frame. The text-fitting function (fitWordText) ran synchronously inside the 60Hz device-motion callback, stalling both the sensor handler and the animation.
  • After: Words now transition with a scale(0.82 → 1.0) pop animation using an overshoot easing curve. This is compositor-only (no layout recalculation). The text-fitting function is deferred to the next animation frame via requestAnimationFrame, so it no longer blocks the sensor path.

Result: smoother, snappier word transitions, especially noticeable during tilt-controlled gameplay.

Re-Test Manual

Verification steps for all 13 failed test cases — for QA tester use

Prerequisites

  • Install the updated Android APK (build from August 29, 2026 or later)
  • Physical Android device with working microphone, auto-rotate capability
  • Clear app data before testing to ensure clean state
  • Have a second device or person available for phone call test

Test 1: F-005 — Sound Toggle

1 Open the app and navigate to the home screen
2 Tap any button and confirm you hear a click/tap sound
3 Tap the 🔊 sound button in the top-right corner
4 Expected: Button icon changes to 🔇, button becomes dimmed (55% opacity)
5 Tap any other button (e.g., "Select Game")
6 Expected: No audio plays while muted
7 Tap the 🔇 button again to unmute
8 Expected: Button returns to 🔊, a tap sound plays confirming audio is restored
9 Start a game round while muted — confirm no sounds during gameplay (correct, skip, timer, etc.)

Test 2: F-006 — Fullscreen Button (Confirm By Design)

1 Open the app on Android
2 Observe the home screen
3 Expected: No fullscreen button is visible. The app already runs fullscreen in the native shell. This is correct behavior.
4 Compare: open https://whambam.games in Chrome on the same device
5 Expected: A "⛶ Fullscreen" button appears in the web version (bottom-right) because the browser has a URL bar to hide

Test 3: F-015 — Timer Stepper (Confirm 5s Step)

1 Navigate to any game mode setup screen
2 Locate the Round Timer stepper (+ / − buttons)
3 Tap the + button once
4 Expected: Timer increases by 5 seconds (e.g., 1:00 → 1:05). This is the intended step size.
5 Verify preset buttons (30s, 45s, 60s, 90s, 2min, 3min) work for quick selection
6 Long-press the + or − button
7 Expected: Timer auto-increments/decrements rapidly in 5s steps while held

Test 4: F-084 — Team Tie Handling

1 Select Up Top, Team mode, 2 teams, 1 round
2 Play Team 1's round — score exactly 2 correct
3 Play Team 2's round — score exactly 2 correct
4 Game Over screen appears
5 Expected: Both teams show 🥇 (same rank). Winner text reads "🤝 It's a tie! [Team 1] & [Team 2] tied with 2 points!" Confetti fires.
6 Repeat with 3 teams where 2 teams tie for 1st and 1 team is lower
7 Expected: Two teams show 🥇, one team shows 🥉 (3rd). Tie message names both winning teams.

Test 5: F-112 — Session Resume Timer Preservation

1 Start a game (any mode, 60s timer)
2 Play until ~30 seconds remain on the timer
3 Force-close the app (swipe it away from recent apps)
4 Reopen the app
5 Expected: "Game in progress" prompt appears with game details
6 Tap "Resume game"
7 Play through to the Ready screen and start the next round
8 Expected: Timer starts from approximately 30 seconds (the remaining time), NOT from 60 seconds

Test 6: M-011 — Voice Command "Yes" (Confirm Limitation)

1 Enable voice commands in setup, start an Up Top round
2 Say "Correct" clearly
3 Expected: Registered consistently
4 Say "Yes" clearly (repeat 5 times across different words)
5 Expected: Recognized in most attempts but may occasionally require repetition. The mic pill shows "listening…" and displays 🎙️ "Yes" → ✓ Correct! when recognized. This is a known speech recognition limitation for short words.
6 Note: "Correct" is the recommended primary trigger word for reliability

Test 7: M-023 — Android Auto-Rotate Instructions

1 Disable auto-rotate on the Android device (enable Portrait Lock)
2 Start an Up Top game and reach the "Rotate Phone" screen
3 Tap "👆 Show Me How to Unlock"

Step 1: "Swipe down from the top of the screen — swipe twice to expand Quick Settings"
Step 2: "Look for the Auto-rotate tile (🔄 icon). If it says Portrait or shows a lock icon, tap it to switch to Auto-rotate"
Step 3: "Rotate your phone sideways — the screen should follow!"
5 Verify steps match the actual Android Quick Settings panel on the test device

Test 13: P-022 — Ad Cannot Be Closed via Back Button

1 Play enough rounds to trigger an interstitial ad (every 3rd round after the grace period)
2 Alternatively: use a free deck, exhaust 50 free words, tap "Watch 30s Ad → 30 more words"
3 The ad countdown screen appears (30-second timer)
4 Press the Android Back button (hardware or gesture) while the countdown is running
5 Expected: Nothing happens. The ad screen remains active. The back button has no effect.
6 Wait for the "✕ Close ad" link to appear (after ~5 seconds)
7 Tap "✕ Close ad" before countdown completes
8 Expected: Returns to setup screen. No words are unlocked (for the rewarded ad path).
9 Repeat, but let the full 30-second countdown complete
10 Expected: "✅ Ad complete!" message, then words are unlocked

Bonus Test: Word Transition Smoothness

1 Start any game mode with tilt controls enabled
2 Tilt the phone to trigger Correct and Skip several times in quick succession
3 Expected: Words transition with a smooth "pop" scale animation (scaling from small to full size with a slight overshoot). No lag or stuttering between words.
4 Also test with button taps in Charades mode (portrait)
5 Expected: Same smooth transition behavior
